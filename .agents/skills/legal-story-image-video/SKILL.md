# 法律故事生图视频：抽象人物 × 写实背景

## 项目定位
这是**独立的图像生成与图生视频工作流**。以生成/复用透明 PNG 角色、写实背景图和局部图生视频为基础，通过时间线剪辑生成成片。无需使用任何既有代码动效项目的工程、目录、组件、脚本、时间轴协议或渲染门禁。

## 使用入口
当用户提供法律题材、生活故事、文案或参考视频，要求制作“抽象小人置于真实世界”的视频时使用。优先交付：角色设定、角色透明 PNG、场景无人物底图、分镜表、图生视频片段、配音、字幕和可独立剪辑的项目资料。工具的具体选择由实际可用性决定。

## 视觉规则（最高优先级）
- **人物与背景必须分开生成、分别管理**。合成时再叠加，不让生成器自行将人物画成真人或日漫。
- 人物：白色圆头或极简白脸、黑色点眼、简化眉/嘴、粗黑描边、少量平面色块、简单手脚。无鼻梁、皮肤纹理、写实五官。需要严格复刻抽象程度时**禁止头发或仅保留抽象标识**；角色唯一性主要依靠服装、眼镜、姿态和配件。
- 背景：写实或高真实感的当代中国场景，真实建筑比例、家具、材质、天气和电影光影。背景图**不包含任何人物**，不自带字幕、logo、错误法律文字。
- 角色素材：以透明 RGBA PNG 或透明 SVG 存储，导出后检查 alpha 像素与边缘，不能用黑/白底冒充透明。
- 情绪：使用姿势、点眼眉嘴、景别、光线和氛围表达。希望阶段偏暖，风险阶段偏冷，尾声克制。
- 律师与故事主人公严格分开：律师角色保留眼镜、黑袍、红领带；购房者用蓝卫衣及背包，其他家庭角色单独编号。

## 标准工作流
1. **选题与法律事实核验**：制作 `research.md`，列出公开来源、事实与争议、法律适用时间、隐私脱敏点；虚构或拼合情节标注“情景演绎”。
2. **写故事**：以“普通人的生活—选择—危机—代价—求助—法律方法—情绪落点”为弧；律师旁白与当事人第一人称叙事不要混为同一真实身份。
3. **角色定妆**：根据 `../../../references/character-manifest.example.json` 定义每一角色的 `character_id`、统一比例、服装和标准表情；先固定正面形象，再制作侧面/背面/表情/动作。**不要每镜头重新随机生成**。
4. **透明人物制图**：先产出单个人物单姿态，检查角色头部、服装颜色、线条粗细与透明 alpha，再批量派生。人物一张一文件。
5. **写实背景生图**：按镜头单独生成人物不存在的背景板，保留角色放置区，优先 16:9 横屏，可根据平台另外做 9:16 竖屏构图。记录色温、光源、地面和机位。
6. **分镜与素材表**：使用 `../../../references/shot-list-template.csv`。每镜头说明 `background_id`、`character_id`、动作、时长、景别、镜头运动、音效、是否需要图生视频。
7. **静态合成/图生视频**：普通镜头使用人物 PNG＋背景静帧＋轻推拉/平移；需要真实动作的少数镜头才使用图生视频或角色局部动画。优先控制跨帧人物形状、手脚和衣物颜色不漂移。
8. **配音与字幕**：以定稿生成旁白音频，利用字幕对齐工具生成校准后的 SRT；镜头时长跟随真实音频而不是估算字数。
9. **剪辑与声音**：在独立视频剪辑项目中叠加人物、写实背景、镜头运动、环境音和克制 BGM。可使用任意支持 PNG alpha 和多轨道的剪辑工具，不能依赖特定代码视频框架。
10. **审片与导出**：逐镜检查角色一致性、背景真实感、画面光影融合、字幕安全区、法律信息准确性、音频完整性，导出 mp4 与素材清单。

## 工程文件布局（独立视频项目）
```
STORY_PROJECT/
  research.md
  story-script.md
  characters/             # 角色透明 PNG
  backgrounds/            # 无人物写实场景图
  shot-list.csv
  image-to-video/          # 需要动作的生成视频片段
  audio/                   # 旁白/BGM/环境音
  subtitles/               # SRT
  editing/                 # 剪辑工程或 EDL
  exports/                 # 最终 MP4
```

## 基础制作比例与运镜
- 默认 1920×1080、16:9、30fps；用户明确要求时改为相应平台规格。
- 普通镜头可先采用 4–7 秒，按照旁白语义伸缩；静态背景轻推镜约 2%–5%，避免明显漂移。
- 关键场景才安排复杂图生视频（行走、回头、拥抱、雨中转身等）。
- 人物与场景的透视协调，脚部接地并加柔和投影；雨景要同步人物受雨状态。

## 提示词与验收
- 人物及背景的分离提示词见 `../../../references/prompts.md`。
- 角色清单示例见 `../../../references/character-manifest.example.json`。
- 本仓库提供 `assets/characters/vector/` 下的透明 SVG 抽象角色母版，可在剪辑前导出 RGBA PNG。先前独立 ZIP 内的 8 张 PNG 属概念初版，尚未作为仓库正式母版。正式制作须先通过角色定妆核验。
- 验收时先检视 3 个关键静帧（希望／危机／法律帮助），再制作 20–30 秒试片，确认风格后再扩展全片。

## 本仓库调用与交付补充
- 每次启动先读仓库根目录 `AGENTS.md` 和 `README.md`，不要推断其他仓库的工具可用。
- 本仓库角色母版位于 `assets/characters/vector/`；含 SVG 透明底，按当期剪辑需要导出 PNG 后再合成。生成式人物须与母版比对。
- 先提交角色对照图、3 张无字关键帧及 20–30 秒试片；仅已渲染和审核的视频才可称作“已生成成片”。
- 生产实例统一放在仓库外独立工程；本仓库保留可复用 Skill、模板、资产与必要版本信息。


## 防止退化为动态PPT（强制）
- 每期必须读 `../../../docs/reference-style-qa.md`，并逐项填写 visual-qa.md。
- 不得把几何矢量场景、模糊插画背景、大标题面板、播放器式边框和统一站立小人当作“电影级生图视频”。
- 背景必须是独立生图/真实空间环境素材，人物保持透明分层，按照镜头交互真正融合，包含真实遮挡、阴影与不同景别。
- FFmpeg 只负责后期编码与剪辑，不替代图像生成与图生视频；若缺可用的图生视频能力，只能交付静态图或明确的非动画样片，不得夸称达到原片动画效果。
- A151 在2026-11-05产出的第一版动态 PPT MP4 已被判定为 REJECTED，不可作为成品参考。


## 人物小、画面多、镜头稳（补充强制规则）
- 用户要求“人物不要占据画面太大比例”，并非要求把人物缩小。人物必须与同深度的沙发、病床、桌椅、门窗保持真实比例；比例由镜头景别与真实透视决定，禁止任何8%–18%统一人物高度硬限制，详见 `../../../docs/perspective-and-framing.md`。
- 对203秒 A151 视频制定52个独立镜头/独立背景生图，**不能**用三张图通过裁切/平移复用成36个镜头来充数；每张应有真实新文件和独立构图。
- 为防抖默认镜头静止，动镜头只做单向1.5%以内缓慢推拉、0.3%以内平移，无随机震荡、无频繁反向；视觉重心锁定。
- 相关执行资料：`../../../episodes/A151/v3/scene-plan.json`、`../../../episodes/A151/v3/image-prompts.md`、`../../../episodes/A151/v3/QUALITY_GATES.md`。
